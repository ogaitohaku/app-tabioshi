# タビオシ

推しの旅を、そのまま予約。旅インフルエンサーの動画に出てきた宿・お店・回った順番を、自分の旅にできる Web アプリ(スマホのホーム画面に置けます)。

> いまはサンプルデータで動いています。人物・宿・お店・料金・口コミはすべて架空です。

## できること

| 画面 | 内容 |
| --- | --- |
| はじめての方へ `/welcome` | 合言葉、使い方の4ステップ、試作であること、予約・支払いは外部サイトで行うこと |
| ホーム `/` | はじめての案内、あなた向けの旅、エリア、推しの旅人、推しが泊まった宿、今日の1問 |
| 旅ショート `/shorts` | 1本ずつ縦にスワイプする旅動画。出典の一行、泊まった宿(予約先があれば「空室を見る」)、「まるごとコピー」 |
| 旅 `/trips/[id]` | 出典、動画に出てくる順の旅程と地図、場所ごとの「行きたい」、1人あたりの目安、予習の豆知識とクイズ、共有 |
| 宿・お店 `/places/[id]` | 推しのひとこと、出典、「行きたい」「行った」、地図で開く、料金、口コミ、予約ボタンと実際の予約先、PR表示 |
| エリア `/areas/[id]` | その街の推しの旅と、宿・ごはん・お土産・スポット |
| 推し `/creators/[id]` | プロフィールと旅の一覧 |
| 旅マップ `/map` | 指で回して拡大できる地球儀。推しが行った場所のピン |
| 行き先をいっしょに決める `/pick` | 旅や場所を2〜6つ選んでリンクを作り、同行者に送る。相手は登録なしで「行きたい」を押して送り返す。名前と票はリンクの # の後ろだけに入り、サーバーには届かない |
| マイ旅 `/me` | コピーした旅と「行きたい」の場所。エリアごと／旅先では近い順、「行った」の数(いまはこの端末にだけ保存) |
| 旅タイプ診断 `/type` | 20問の旅タイプ診断(試作)、16タイプの結果、友だちとの相性 |

## 動かし方

Node.js 22 以上が必要です。

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # 本番用にビルド
npm run lint
npm run test:unit      # 予約先の表示・相談リンク・掲載前チェックの単体テスト
npm run check:content  # 掲載前チェック(同意・元の投稿・確認日・予約先)。本物のデータでは要対応が残ると失敗
```

画面を通しで確かめるときは、`npm run build && npx next start -p 3100` のあと、Playwright が入った環境で次を動かします。

```bash
BASE=http://localhost:3100 node tests/e2e/flow.cjs        # 今回の流れ(動画→場所→保存→旅先で再発見)
BASE=http://localhost:3100 node tests/e2e/pick.cjs        # 行き先をいっしょに決める(3人で送り合う)
BASE=http://localhost:3100 node tests/e2e/regression.cjs  # これまでの画面と操作
```

## この端末に保存するデータ

ログインがまだないため、利用者のデータはブラウザ(localStorage)にだけ保存します。キーの名前と形は、版を上げても変えません。

| キー | 中身 |
| --- | --- |
| `tabioshi.savedTrips` | まるごとコピーした旅のID(文字列の配列) |
| `tabioshi.myPlaces` | 「行きたい」と「行った」の場所ID → 日時 |
| `tabioshi.plans` | 行き先の相談(候補と、送り返された票を合わせたもの。新しい順に20件)と、自分の呼び名 |
| `tabioshi.prefs` | あなた向けの好み |
| `tabioshi.dailyQuiz` | 今日の1問の記録 |
| `tabioshi.type` | 旅タイプ診断の結果 |
| `tabioshi.welcome` | はじめての案内を閉じたか |

## 中身(コンテンツ)の差し替え

- 人物・動画・宿・お店・クイズは `src/data/sample.ts` にあります。型は `src/data/types.ts`。
- 写真は `public/photos/` に置いて、`visual.photo` に `/photos/ファイル名.jpg` を書くと、イメージ画像の代わりに表示されます。
- 宿の予約先は `stay.booking` に書きます。
  - 楽天トラベルの施設番号: `{ rakutenHotelNo: "12345" }`
  - それ以外の予約サイト: `{ url: "https://..." }`(紹介リンクのときだけ `affiliate: true`)
  - 画面には、実際につながっている予約先(紹介リンク/通常のリンク/準備中)がそのまま出ます
- 掲載料をもらっている宿・お店は `sponsored: true` にすると、画面に必ず「PR」と出ます。
- 本物のデータに切り替えたら、`src/data/sample.ts` の `IS_SAMPLE` を `false` にすると「サンプルです」の注記が消えます。
- 投稿者には `consent: { agreedAt, scope }`(掲載の同意をいつ・何についてもらったか)を書きます。公開前に `npm run check:content` で、同意・元の投稿のリンク・情報の確認日(180日以内)・予約先の抜けを確かめます。

## 予約のしくみ

タビオシでは予約を受けず、楽天トラベルなどの予約サイトに送ります(アフィリエイト)。楽天アフィリエイトの紹介IDを環境変数 `NEXT_PUBLIC_RAKUTEN_AFFILIATE_ID` に入れると、予約ボタンが紹介リンクになります。`.env.example` を参照してください。

## 公開(デプロイ)

Vercel か Netlify にこのリポジトリをつなぐと、`main` に入るたびに自動で公開されます。環境変数 `NEXT_PUBLIC_RAKUTEN_AFFILIATE_ID` は公開先の設定画面で入れてください。

## 次にやること

- 旅タイプ診断を OGATYPE v2(OGA 共通の診断)に切り替える。採点の仕組みは OGATYPE チームのものを使い、ここでは作らない
- 実在のクリエイターと掲載データへの入れ替え、楽天アフィリエイトIDの設定
- ログインとデータベース。マイ旅を端末をまたいで保存する
- 規約類を OGA 共通のひな形に合わせて仕上げ、専門家の確認を受ける

予約と旅行代金の支払いは、これからも外部の予約サイトで行います(旅行業の登録がないため)。

## 見た目のルール

OGA 統一ルール(明るい業務サービス風)に合わせています。白地＋グレー＋朱1色、グラデーション・すりガラスなし、文字は12px以上、ボタンは44px以上。

## 地図データ

地球儀の陸地は [Natural Earth](https://www.naturalearthdata.com/)(パブリックドメイン)をもとにしています。
